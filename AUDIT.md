# Аудит KodShkola — этап 1

## Состав проекта
- Flask application factory и 5 Blueprint: main, auth, student, teacher, admin.
- SQLite через sqlite3, Jinja2, Markdown, CSS и JavaScript без frontend-фреймворка.
- 11 таблиц в `edu/schema.sql`: users, categories, courses, sections, lessons,
  code_examples, assignments, enrollments, lesson_progress, submissions, notifications.
- Реализованы регистрация/вход/выход, роли, каталог, запись на курс, текстовые уроки,
  примеры кода, отправка работ, ручная проверка, оценки, прогресс и уведомления.
- Есть демонстрационное наполнение `seed.py` и сквозной тестовый сценарий.

## Исправления в этом проходе
1. Удалено `or True` из проверки доступа преподавателя к чужой работе:
   ранее этот тест всегда проходил независимо от результата запроса.
2. Добавлена условная зависимость `tzdata` для Windows, где база часовых поясов
   для `zoneinfo.ZoneInfo("Europe/Moscow")` может отсутствовать.
3. Исправлено описание количества таблиц в README: в текущей схеме их 11, а не 12.

## Выявленные пробелы относительно ТЗ
- Нет системы обращений в поддержку (таблиц и маршрутов).
- Нет резервного копирования/восстановления SQLite.
- Нет журнала важных действий пользователей.
- В текущей админ-панели есть управление пользователями, ролями, курсами и категориями,
  но нет подтверждения преподавателей и отдельного интерфейса обращений/резервных копий.
- Существующая схема инициализируется через `CREATE TABLE IF NOT EXISTS`; отдельной
  версионированной системы миграций пока нет.
- Ограничение попыток входа хранится в памяти процесса, поэтому не является общим
  для нескольких Gunicorn workers и сбрасывается при перезапуске.
- В тестах был один заведомо пропускающий проверку (`... or True`); он исправлен.
- CSS уже содержит адаптивную оболочку и переменные, но текущая палитра/каркас
  отличаются от целевого фирменного направления из ТЗ; полноценный редизайн ещё впереди.

## Проверка в текущей среде
- `python -m pytest -q` не смог даже собрать тесты: в среде отсутствует Flask.
- Установка зависимостей из `requirements.txt` не удалась, так как среда не имеет
  доступа к PyPI (ошибка DNS). Поэтому функциональные тесты пока не запускались.
- Следующий корректный шаг — запуск тестового сценария в окружении с установленными
