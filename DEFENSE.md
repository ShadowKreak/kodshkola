# KodShkola — материалы для защиты курсовой работы

Тема: «Внедрение и поддержка платформы для проведения курсов и занятий».

## 1. Краткое описание для комиссии

KodShkola — веб-платформа для изучения программирования без видеоуроков. Преподаватель создаёт курс из разделов, уроков (текст с форматированием и примерами кода) и практических заданий. Студент записывается на курс, читает уроки, сдаёт задания и получает оценку от 1 до 10 с комментарием. Администратор управляет пользователями, ролями, курсами и категориями.

**Актуальность.** Дистанционное обучение программированию требует не просмотра видео, а практики и обратной связи. Платформа реализует именно этот цикл: теория → пример кода → задание → проверка человеком → исправление → оценка. Прогресс сохраняется, обучение продолжается с последнего открытого урока.

**Технологии.** Python 3, Flask (блюпринты, шаблоны Jinja2), SQLite, HTML/CSS/JavaScript без внешних фреймворков, библиотека Markdown для текста уроков.

## 2. Архитектура

Flask-приложение собирается фабрикой `create_app()` (`edu/__init__.py`). Пять блюпринтов:

| Блюпринт | Назначение |
|---|---|
| `main` | главная страница, каталог курсов, API предпросмотра Markdown |
| `auth` | регистрация, вход, выход, профиль |
| `student` | кабинет студента: курсы, уроки, задания, оценки, прогресс |
| `teacher` | кабинет преподавателя: курсы, структура, проверка работ, статистика |
| `admin` | пользователи, курсы, категории, общая статистика |

Слои: маршруты (`blueprints/`) → бизнес-логика (`services.py`: прогресс, статусы, «следующий шаг») → доступ к данным (`db.py`, SQL с параметрами) → шаблоны (`templates/`, макросы в `_m.html`). Безопасность — в `security.py` (роли, CSRF, ограничение попыток входа), очистка HTML — в `content.py`.

## 3. Основные таблицы БД

| Таблица | Назначение |
|---|---|
| `users` | пользователи: e-mail, имя, хеш пароля, роль (student/teacher/admin), блокировка |
| `categories` | категории курсов |
| `courses` | курсы: преподаватель-автор, уровень, категория, обложка, признак публикации |
| `sections` | разделы курса с порядком |
| `lessons` | уроки раздела (текст в Markdown) |
| `code_examples` | примеры кода к уроку (язык, код) |
| `assignments` | задания курса: практика или итоговый проект, срок |
| `enrollments` | записи студентов на курсы (уникальная пара студент–курс) |
| `lesson_progress` | уроки, отмеченные студентом как изученные |
| `lesson_visits` | последний открытый урок — для кнопки «Продолжить обучение» |
| `submissions` | попытки сдачи заданий: текст ответа, статус, оценка 1–10, комментарий; каждая попытка отдельной строкой |
| `notifications` | уведомления о проверке и новых работах |

Связи: курс → разделы → уроки → примеры кода; студент ↔ курс через `enrollments`; задание → попытки в `submissions`. Внешние ключи включены (`PRAGMA foreign_keys = ON`), оценка ограничена CHECK 1–10, пара (задание, студент, номер попытки) уникальна.

## 4. Роли и функции

**Студент:** регистрация и вход; каталог и запись на курс; чтение уроков, отметка «изучено»; сдача и повторная сдача заданий; просмотр оценок и комментариев; прогресс по курсам; кнопка «Продолжить обучение»; уведомления; профиль.

**Преподаватель:** создание и редактирование только своих курсов; разделы, уроки (редактор Markdown с предпросмотром), примеры кода, задания; публикация курса; список студентов и их прогресс; проверка работ (оценка 1–10, комментарий, возврат на доработку); статистика курса.

**Администратор:** сводка (студенты, преподаватели, курсы, опубликованные курсы, записи, сданные и ожидающие проверки работы); пользователи (поиск, смена роли, блокировка, удаление); курсы (скрыть/показать, удалить); категории.

## 5. Принципы работы

**Запись на курс.** Студент нажимает «Записаться» в каталоге → создаётся строка в `enrollments` → курс появляется в «Мои курсы».

**Прохождение урока.** Урок открывается → фиксируется `lesson_visits` → студент нажимает «Отметить изученным» → строка в `lesson_progress`.

**Сдача и проверка.** Студент отправляет решение → `submissions` со статусом «На проверке», преподавателю уходит уведомление → преподаватель ставит оценку («Проверено») или возвращает на доработку («Требуются исправления») → студент получает уведомление и может отправить новую попытку.

**Прогресс** = (изученные уроки + проверенные задания) / (все уроки + все задания).

## 6. Сценарий демонстрации (≈10 минут)

Запуск: `python seed.py`, `python run.py`, открыть http://127.0.0.1:5000. Пароль демо-аккаунтов — `Demo12345`.

1. **Главная.** Показать реальные курсы из БД, пример кода, описание процесса проверки.
2. **Студент** (`anna@kodshkola.local`, либо новая регистрация): «Каталог» → запись на курс → открыть урок, показать пример кода и кнопку копирования → «Отметить изученным» → открыть задание, отправить решение → статус «На проверке» → на панели показать «Продолжить обучение» и прогресс.
3. **Преподаватель** (`ivanova@kodshkola.local`): «Проверка работ» → открыть работу → поставить оценку и комментарий (или вернуть на доработку) → «Мои курсы» → структура курса, добавить урок в редакторе с предпросмотром, добавить задание, опубликовать.
4. **Студент:** обновить страницу — уведомление, оценка и комментарий, изменившийся процент прохождения.
5. **Администратор** (`admin@kodshkola.local`): сводка → «Пользователи» (поиск, смена роли, блокировка) → «Курсы» (скрыть/показать) → «Категории» (добавить).
6. **Безопасность:** попытка студента открыть `/teacher/` → 403.

## 7. Возможные вопросы комиссии

**Почему Flask и SQLite?** Flask прост и хорошо подходит для учебного проекта с понятной структурой; SQLite не требует отдельного сервера, база — один файл, схема совместима с переносом на PostgreSQL.

**Как хранятся пароли?** Только в виде хеша scrypt с солью (Werkzeug); пароль в открытом виде нигде не сохраняется.

**Как разграничен доступ?** Проверка роли выполняется на сервере в каждом блюпринте и в каждом маршруте; преподаватель работает только со своими курсами, студент видит только свои работы. Попытка зайти в чужой раздел даёт 403.

**Как защищено от XSS и CSRF?** Текст уроков очищается белым списком тегов, шаблоны экранируют вывод, заголовок CSP запрещает чужие скрипты; все POST-запросы требуют CSRF-токен.

**Почему оценки не считаются автоматически?** Цель платформы — обратная связь от преподавателя; задания проверяет человек, студент видит комментарий и может исправить работу.

**Что если студент отправит работу повторно?** Создаётся новая попытка, история предыдущих сохраняется.

**Как масштабировать?** Запуск через gunicorn за HTTPS-прокси, переход на PostgreSQL, вынос счётчика попыток входа в БД; новые функции (квизы, сертификаты) добавляются новыми таблицами.

**Что не реализовано?** Автопроверка кода, тесты с вариантами ответов, e-mail-уведомления, резервное копирование и поддержка — они не входили в итоговое задание и описаны как направления развития.
